# سراج

تدريب يومي لكفاءات الرقابة والتوطين.

## ملفات المستودع

| الملف | وظيفته |
|---|---|
| `index.html` | التطبيق كاملاً. لا تحتاج تعديله أبداً. |
| `config.json` | إعدادات احتياطية. بعد التفعيل تُحفظ الإعدادات في جدول Google ولا تحتاج تعديل هذا الملف. |
| `.nojekyll` | ملف فارغ يحتاجه GitHub Pages. |

## التشغيل (مرة واحدة فقط)

1. ارفع هذه الملفات إلى المستودع مكان القديمة. هذه آخر مرة ترفع فيها شيئاً إلى GitHub.
2. افتح سراج. ستظهر شاشة **تسجيل الدخول**: الاسم والإدارة.
3. اضغط شعار سراج **٥ مرات متتالية** لصفحة الإدارة. الرمز المبدئي `1234`، غيّره.
4. اضغط **"فعّل الآن"** واتبع الخطوات داخل سراج:
   - جدول Google جديد.
   - زر "انسخ الكود" ثم لصقه في Apps Script.
   - نشره ولصق رابطه.
5. انسخ **رابط سراج للموظفين** الذي يظهر لك، وأرسله لفريقك.

## بعد ذلك

- لا نشر ولا GitHub ولا ملفات. كل ما تحفظه في صفحة الإدارة يصل للموظفين خلال ثوانٍ، ومن كان سراج مفتوحاً عنده يصله خلال نصف دقيقة. هذا يشمل:
  - موضوع التركيز.
  - إيقاف سؤال أو إضافته.
  - الرسالة للموظفين.
- أسماء الموظفين وتقدّمهم تظهر في "لوحة متابعة الموظفين"، وفي ورقة "الموظفون" بجدول Google.
- من فتح سراج من الرابط العادي قبل التفعيل يكفيه أن يفتح رابط الموظفين مرة واحدة. يرتبط ويبقى اسمه وتقدّمه كما هو.

## ملاحظات

- الدليل الإجرائي مصنّف "مقيد" وللاستخدام الداخلي في الوزارة. أبقِ المستودع خاصاً، وشارك الرابط مع منسوبي الوزارة فقط.
- انتبه: كون المستودع خاصاً لا يجعل موقع GitHub Pages خاصاً. الموقع يبقى مفتوحاً لمن يعرف رابطه، ما لم يكن حساب الوزارة على GitHub Enterprise Cloud واخترت في إعدادات Pages أن يكون الوصول لأعضاء المنظمة فقط. نشر Pages من مستودع خاص يحتاج أصلاً خطة GitHub مدفوعة.
- بيانات المتابعة تُحفظ في جدول Google الذي ينشئه المشرف. إذا كانت سياسة الوزارة تمنع ذلك، يمكن لفريق التقنية إنشاء خدمة داخلية بنفس الواجهتين:
  - `POST`: يستقبل ملخص تقدم الموظف بصيغة JSON.
  - `GET ?key=…`: يعيد `{ok:true, rows:[…]}`.

  ثم يُلصق رابط الخدمة الداخلية بدل رابط Google.
